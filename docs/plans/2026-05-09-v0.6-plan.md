# FlyupMem v0.6 Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** 三个产品级改进 — 异步写入队列/并发安全、Experience 层自动归纳、Dashboard 管理 UI 增强。

**Architecture:** 在现有文件锁+atomic write 基础上增加异步写入队列；新增 Experience interface 和自动归纳 pipeline；Dashboard 新增 maintain/reflect/create/semantic-search 功能。

**Tech Stack:** TypeScript, Vitest, Node.js fs, SQLite, YAML, HTML/JS (vanilla)

---

## Phase 1: 异步写入队列 / 并发安全

### 现状分析

当前 `store.ts` 已有：
- ✅ 文件锁（`O_EXCL` + 重入计数 + 15s 过期清理）
- ✅ Atomic write（tmp + rename）
- ✅ 3-way merge（snapshot-based）
- ❌ 全部同步阻塞（`fs.*Sync`），Node 事件循环被阻塞
- ❌ 无写入队列，多端同时调用 `save()` 靠锁串行但无排队
- ❌ `sleepSync` 用 `Atomics.wait` 阻塞主线程

### Task 1.1: 创建 WriteQueue 类

**Objective:** 实现一个进程内异步写入队列，所有写操作排队串行执行，不阻塞调用方。

**Files:**
- Create: `src/core/write-queue.ts`
- Test: `tests/write-queue.test.ts`

**设计：**

```typescript
// src/core/write-queue.ts
export class WriteQueue {
  private queue: Array<{ fn: () => void; resolve: () => void; reject: (e: Error) => void }> = []
  private running = false
  private drainResolvers: Array<() => void> = []

  enqueue(fn: () => void): Promise<void>     // 排队一个写操作
  drain(): Promise<void>                      // 等待队列清空（用于 shutdown/test）
  get pending(): number                       // 队列长度
  private async processNext(): Promise<void>  // 串行执行下一个
}
```

**核心逻辑：**
- `enqueue()` 返回 Promise，调用方可选 await 或 fire-and-forget
- 内部串行处理，一个完成才执行下一个
- 锁仍然在 `save()` 内部持有（跨进程安全），队列只解决进程内排队

**Step 1:** 写测试 — 验证串行执行、并发 enqueue 不丢失、drain 等待清空
**Step 2:** 实现 WriteQueue
**Step 3:** 跑测试
**Step 4:** Commit `feat: add WriteQueue for async serial write operations`

### Task 1.2: Store 集成 WriteQueue

**Objective:** 给 `FlyupMemStore` 加 `saveAsync()` 方法，内部用 WriteQueue。

**Files:**
- Modify: `src/core/store.ts`
- Test: `tests/write-queue.test.ts`（追加集成测试）

**设计：**

```typescript
// store.ts 新增
private writeQueue = new WriteQueue()

saveAsync(): Promise<void> {
  return this.writeQueue.enqueue(() => this.save())
}

async shutdown(): Promise<void> {
  await this.writeQueue.drain()
}
```

- 现有 `save()` 保持不变（向后兼容，同步场景仍可用）
- 新增 `saveAsync()` 供插件和 Dashboard 使用
- `shutdown()` 在进程退出前调用，确保队列清空

**Step 1:** 写测试 — 并发 saveAsync 不丢数据、shutdown 等待完成
**Step 2:** 集成到 store.ts
**Step 3:** 跑全套 vitest
**Step 4:** Commit `feat: integrate WriteQueue into FlyupMemStore`

## Phase 2: Experience 层自动归纳

### 现状分析

- `Layer` type 已有 `'experience'`，`LAYER_ORDER` 位置 4
- 无 `Experience` interface
- `Memory` union 未包含 Experience
- 现有 pipeline: Engram → consolidate → Observation → reflect → MentalModel
- 缺第四层: 从多个相关 MentalModel 归纳出 Experience

### Task 2.1: 定义 Experience 类型

**Objective:** 在 types.ts 中定义 Experience interface 并加入 Memory union。

**Files:**
- Modify: `src/core/types.ts`
- Test: `tests/types.test.ts`（如有）或直接编译验证

**设计：**

```typescript
export interface Experience {
  id: string                          // EXP-YYYYMMDD-NNN
  layer: 'experience'
  status: Status
  scope: string
  domain: string
  tags: string[]
  title: string                       // 一句话概括
  statement: string                   // 完整归纳

  // 溯源
  source_model_ids: string[]          // 来源 MentalModel IDs
  source_observation_ids: string[]    // 间接来源 Observation IDs
  evidence_chain: Array<{
    model_id: string
    observation_ids: string[]
    confidence: number
  }>

  // 元数据
  proof_count: number
  confidence: number
  trend: 'new' | 'strengthening' | 'stable' | 'weakening' | 'stale'

  activation: Activation
  emotional_weight: number
  entities: Entity[]
  temporal: Temporal
}

export type Memory = Engram | Observation | MentalModel | Experience
```

**Step 1:** 修改 types.ts
**Step 2:** 编译验证 `npx tsc --noEmit`

### Task 2.3: 自动归纳 Pipeline

**Objective:** 创建 `induceExperience()` 函数，从相关 MentalModel 自动归纳 Experience。

**Files:**
- Create: `src/lifecycle/induce-experience.ts`
- Test: `tests/induce-experience.test.ts`

**设计：**

```typescript
export interface InductionResult {
  created: Experience[]
  updated: Experience[]
  skipped: number
}

export async function induceExperience(
  store: FlyupMemStore,
  options?: {
    minModels?: number       // 最少几个 MentalModel 才归纳（默认 3）
    similarityThreshold?: number  // 相关度阈值（默认 0.7）
    llmClient?: LLMClient    // 可选 LLM 增强
  }
): Promise<InductionResult>
```

**归纳逻辑：**
1. 取所有 active MentalModel
2. 用 embedding 聚类（复用 `clusterByEmbedding`）
3. 每个 cluster ≥ minModels 个模型 → 归纳候选
4. 如有 LLM：调用 LLM 合成 Experience statement
5. 如无 LLM：用 BM25 关键词提取 + 模板拼接
6. 检查是否已有相同 domain+scope 的 Experience，有则 update（strengthening），无则 create
7. 保留完整 evidence_chain

**Step 1:** 写测试 — 3 个相关 MentalModel 归纳出 1 个 Experience
**Step 2:** 写测试 — 不相关 MentalModel 不归纳
**Step 3:** 写测试 — 已存在 Experience 则更新 trend
**Step 4:** 实现 induceExperience
**Step 5:** 跑测试
**Step 6:** Commit `feat: Experience auto-induction pipeline`
