# Security policy

## Supported version

Security fixes target the latest version on the default branch.

## Reporting a vulnerability

Please avoid publishing a vulnerability or proof of concept in a public issue
before the maintainer has had an opportunity to investigate it. Send a concise
report to the repository owner through GitHub with:

- affected version and component
- reproduction steps or a minimal proof of concept
- impact assessment
- suggested mitigation, if available

Reports involving memory disclosure, unsafe tool invocation, path handling,
schema migration, plugin boundaries, or dependency behavior are especially useful.

The maintainer will acknowledge the report, investigate it, and coordinate a fix
or a public disclosure timeline through GitHub.
